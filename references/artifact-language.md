# Clear language for visual artifacts

## Keep one language

- Default the artifact to US English. A chat message written in another language does not by itself change the artifact language.
- Use another language only when the user explicitly requests it for the artifact or the named audience or project convention requires it.
- Use it consistently for headings, prose, diagrams, controls, narration, and captions.
- Use the project's English variant when it specifies one.
- Preserve exact product names, API names, commands, paths, code identifiers, enum values, and UI labels. Do not use English verbs or connectors merely because the subject is technical.
- Keep a quotation in its source language only when the exact wording is evidence; translate or explain it nearby when the reader needs that help.

## Write standard technical English

- Use conventional subject–verb–object order. Keep the actor and action near the start.
- Prefer active voice when the actor matters and present tense for current behavior.
- Address the reader as `you`; use the imperative for procedures.
- Put a condition before its instruction: “If the lease expires, retry the claim.”
- Keep one main idea per sentence. Split clause chains without making the prose choppy.
- Use one term for one concept with consistent spelling and capitalization.
- Prefer direct verbs and concrete nouns. Remove filler, vague pronouns, modifier stacks, idioms, slang, cultural jokes, and ornamental metaphors.
- Use an established technical term when it is more precise; define an unfamiliar term on first use. Do not invent synonyms for variety.
- Make lists parallel and keep facts, actions, questions, and proposals distinct.
- Replace `simply`, `easy`, and `obviously` with the actual action or constraint.

## Review

- Can the reader identify the actor, action, condition, and result?
- Does every important concept have one searchable term?
- Does every language switch preserve evidence or necessary terminology?
- Can an international reader understand the text without decoding an idiom or cultural reference?

Basis: [Google developer style](https://developers.google.com/style/translation), [Microsoft global writing tips](https://learn.microsoft.com/en-us/style-guide/global-communications/writing-tips), [Microsoft technical terminology](https://learn.microsoft.com/en-us/style-guide/word-choice/use-technical-terms-carefully), and [GOV.UK clear language](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-language/).
