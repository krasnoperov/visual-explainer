# Dense, Natural Report Design

## Editorial contract

- Start from the reader's situation: what are they trying to understand, and what mistake does a weak reading invite?
- Keep the reasoning causal and conversational: tension → consequence → useful model → evidence → decision. Change the sequence when the subject needs another path.
- Preserve complexity that changes the decision. Remove setup, repetition, boilerplate, and prose that only connects sections.
- Make every word earn its pixels. A label labels; an annotation explains a visible feature; a caption states provenance; body copy advances the reasoning.
- Do not repeat the same claim in a headline, lead, cards, diagram, and conclusion.
- Keep supporting evidence close to the claim it supports. Collapse only raw or optional detail.

## Space economy

- Treat the first phone viewport as working space, not a poster. A title establishes orientation; evidence begins immediately.
- Default to compact sentence-case headings. Reserve display scale for a genuinely short, characteristic phrase and keep useful content visible below it.
- Prefer short sections, tight labelled rows, side annotations, compact tables, and diagrams with text embedded at the relevant point.
- Use whitespace to separate ideas, not to imply luxury. Do not create large empty hero regions or oversized cards around a few words.
- Use one outer reading surface. Separate ideas with alignment, spacing, and neutral rules rather than nested boxes.

## Visual direction

- Ground the look in the subject's materials, instruments, and vocabulary. A system investigation may resemble a trace; a decision may resemble an annotated comparison; a research synthesis may resemble a field notebook.
- Choose one signature device that makes the subject easier to understand. Spend boldness there and keep the surrounding UI disciplined.
- Let structure encode truth. Numbering means sequence; containment means ownership; size means quantity; position means relationship; color means a stable state or category.
- Avoid distributional defaults: warm-cream editorial pages with giant serif headlines, purple gradients, generic dark dashboards, uniform rounded cards, ornamental arrows, and arbitrary metric tiles.
- Use typography as hierarchy, not spectacle. Keep body text comfortable for sustained screen reading; reserve serif/display faces for restrained emphasis; use monospace only for evidence, identifiers, and measured values.

## Representation router

| Reader needs to see | Prefer |
|---|---|
| Ordered change or lifecycle | Timeline, storyboard, or vertical step flow |
| Several inputs becoming one result | Convergence map |
| One cause creating several effects | Fan-out or causal tree |
| Ownership, containment, or taxonomy | Tree or nested regions |
| Input transformed into output | Before / process / after |
| Two alternatives or states | Aligned comparison or small multiples |
| Quantity, limit, or proportion | Scale, bar, annotated number, or compact chart |
| Exact mapping, audit status, or failure behavior | Semantic table, matrix, or ledger |
| Spatial mechanism or interface behavior | Annotated illustration or screenshot |
| Dense architecture | Small overview map plus focused sectional zooms |
| A decision with branches | Decision tree or state machine |

Combine forms only when each answers a different question. Do not render every section as the same card, row, or three-step flow.

## Diagram and illustration gates

- State the learning question before drawing.
- Make geometry meaningful even if the labels disappear.
- Use real payloads, events, values, screenshots, quotes, or code fragments where evidence matters.
- Put explanation next to the relevant mark; avoid legends that force eye travel when direct labels fit.
- Use overview → boundary → detail for systems larger than roughly 12–15 nodes. Never shrink labels to preserve one giant diagram.
- Use a simple illustration when it can replace several paragraphs, but do not decorate text with unrelated imagery.
- Keep scales honest: show a defensible denominator and distinguish measured values from illustrative proportions.

## Interaction threshold

- Add filtering, toggles, zoom, or navigation only when they let the reader inspect a real alternate state or evidence slice.
- Do not add controls as proof of sophistication. A static annotated view is better when there is only one useful state.
- Keep the initial state complete enough to understand without interaction.

## Mobile QA

- Render at 360px first. Check how much useful information appears before the first scroll.
- Check reading order, line length, text size, tap targets, focus, contrast, and page-level overflow.
- Stack comparisons without losing their shared labels. Make unavoidable wide code or tables explicitly scrollable.
- Inspect connector collisions, clipped labels, chart legibility, and image crops visually.
- Re-read only the visible copy. Delete any sentence that repeats, announces, or decorates instead of informing.
